# CLAUDE.md

Guidance for AI coding tools (Claude Code, Codex, Cursor) working in this repository.

## What this project is
"Shelfwise POS", a full-stack point of sale and inventory system for a fictional shop. React 19 + Vite 7 front end, a dependency-free Node 22 API, SQLite database. Two roles, `admin` and `cashier`, server-side auth. There are no guest routes: every API route except health, config, login and demo-login needs a signed-in user.

## Layout
`Node API/` (server + tests, own package.json and lockfile), `React Web/` (front end, own package.json and lockfile), `database/` (schema.sql, seed.sql, make_seed.py), `docs/`, `api/` (Vercel demo entry only).

## Commands
- Build: `cd "React Web" && npm ci && npm run build`. Run: `cd "Node API" && npm start` (http://localhost:3000)
- Development: `npm run dev` in `Node API` and in `React Web` (Vite proxies `/api` to :3000)
- Tests: `cd "Node API" && npm test` (`node --test`, in-memory database)
- Regenerate demo data: `python3 database/make_seed.py > database/seed.sql`
- No linter is configured

## Server (`Node API/server/`)
- `index.js` creates the HTTP server: `/api/*` goes to the router, everything else is static files from `dist/`.
- `config.js` reads environment variables and holds shop rules (discount limits, max line quantity). Tax is per product.
- `db.js` opens SQLite (`node:sqlite`), applies `database/schema.sql`, seeds demo data in `DEMO_MODE`, or creates the admin from env vars. `tx()` wraps a transaction.
- `auth.js` scrypt password hashing, session tokens (random, stored as sha256), cookie helpers, in-memory rate limiter. Inactive users cannot sign in or keep a session.
- `routes.js` builds the handler; endpoints live in `routes/` (`system`, `auth`, `products`, `sales`, `purchases`, `reports`, `users`, `admin`). Each handler calls `requireUser` or `requireAdmin` itself. Add a route with `route(method, pattern, handler, { body: true })`.
- `validate.js` input validation. `pos.js` row-to-JSON mapping and `priceSale()`, which prices a basket from database values only.
- `http.js` JSON helpers, security headers, CSRF origin check, static file serving.
- `api/index.mjs` is the Vercel entry (demo hosting only): `STATELESS_SESSIONS=true`, in-memory database. It holds no password; set `DEMO_*_PASSWORD` and `SESSION_SECRET` in the host.

## Database (`database/`)
`schema.sql` is idempotent and runs on every start. `seed.sql` is generated by `make_seed.py` with dates relative to now and loads only into an empty database. Money is integer cents in the database and dollars in the JSON the API returns. Stock changes always write a `stock_movements` row.

## API summary
Public: `GET /api/health|config`, `POST /api/auth/login|logout`, `GET /api/auth/me|demo-login` (demo mode).
Signed in: `GET /api/products|categories`, `POST /api/sales`, `GET /api/sales` (own; admin all), `GET /api/sales/:id` (owner or admin).
Admin only: `POST|PUT|DELETE /api/products`, `POST /api/products/:id/stock`, `GET /api/products/:id/movements`, `POST /api/sales/:id/refund`, suppliers and purchases (`/api/suppliers`, `/api/purchases`, `/receive`, `/cancel`), `GET /api/reports/summary`, `/api/users`, `POST /api/admin/reset-demo` (demo mode only).

## Front end (`React Web/src/`)
- `index.html` (repo `React Web/`) is the plain HTML landing page (`src/landing/landing.css`); the React app is `store/index.html`, served at `/store/`.
- `main.jsx` mounts `<StoreProvider><App/></StoreProvider>`. `api.js` is the fetch wrapper. `store.jsx` holds user, products, categories and the toast. Nothing about sales is kept in the browser.
- `router.jsx` is a hash router (`#/sales`). Use `navigate(to)` and `<Link to>`. Do not add a router library.
- `pages/` one component per route; `components/` shared pieces (`Field`, `Dialog`, `Receipt`, `CartPanel`, forms).
- `styles/index.css` imports the stylesheets in order; design tokens are in `styles/tokens.css`.

## Conventions
- Plain JavaScript (ES modules), JSX function components, no TypeScript, no CSS-in-JS.
- Keep files under about 300 lines.
- Never trust the browser: prices, totals, tax, stock and roles are decided on the server. The terminal sends product ids and quantities only.
- Never define a component inside another component's render (it remounts and inputs lose focus). `Field` and `TextField` live at module level for this reason.
- Every form field has a visible `<label>` and an inline error. No `dangerouslySetInnerHTML`.
- Copy is plain, sentence case, active voice.

## Security notes
- Do not put secrets or passwords in the repo. Demo accounts come from `Node API/server/config.js`, which reads `DEMO_*` variables and never contains a password. They exist only in demo mode.
- Card payments are recorded as a method only. No card data is collected. Use a payment provider's terminal or hosted fields for real card payments.
- Session cookie is HttpOnly and SameSite=Lax. State-changing requests must be JSON and pass an Origin check.
- Add a role check to every new write endpoint and a test for the 401 and 403 cases in `Node API/tests/api.test.js`.

## Common tasks
- **Add a product:** admin, Products, or edit `database/make_seed.py` (demo data only).
- **Add a category:** insert it in `database/schema.sql` (rows at the bottom).
- **Change discount limits:** `Node API/server/config.js` (`pos`).
- **Add a card terminal or payment provider:** create the payment in `Node API/server/routes/sales.js` after `priceSale()`, using the priced total.
- **Re-skin:** tokens in `React Web/src/styles/tokens.css`, logo in `components/Logo.jsx` and `public/favicon.png`.
