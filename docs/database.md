# Database notes

SQLite, created by `database/schema.sql` (idempotent, runs on every start). Demo data: `database/seed.sql`, generated by `python3 database/make_seed.py > database/seed.sql` with dates relative to the current day. It loads only into an empty database when `DEMO_MODE=true`. The two demo users are created by the server with hashed passwords, so no credentials are in any SQL file.

## Rules enforced by the database
- Money columns are integer cents with `CHECK (... >= 0)`.
- `products.stock >= 0`: a sale cannot oversell even if two requests race.
- `users.email`, `products.sku` and `products.barcode` are unique; `users.role` is `admin` or `cashier`.
- `sales.method` is `cash`, `card` or `mobile`; `sales.status` is `completed` or `refunded`; `purchases.status` is `ordered`, `received` or `cancelled`.
- Sale lines copy the product name, SKU, price, cost and tax at the time of sale, so history is correct after later edits.
- `stock_movements` records every change (`initial`, `sale`, `refund`, `purchase`, `adjustment`) with the receipt or order reference.

## Backup and reset
Copy the file while the server is stopped, or `sqlite3 file.db ".backup backup.db"`. In demo mode an admin can restore the sample data from Settings.
